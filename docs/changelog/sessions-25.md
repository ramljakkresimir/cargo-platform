# Implemented Features — Session 25

### Session 25 — 2026-08-27

#### Fix: read-only star fill rendered as a smeared tint instead of a clean split

**Bug report (with screenshot):** the read-only average-rating display (`RatingStars`, shown on `/profile`, listing detail pages, and search result cards) rendered an average of 3.0 with all 5 stars carrying a faint yellowish tint instead of exactly 3 solid gold stars and 2 clean gray ones.

**Root cause:** the previous implementation rendered the gold "filled" layer as **one flex row containing all 5 star icons**, then clipped that row's *container* to `{average/5*100}%` width via `overflow: hidden`. Because the container was `display: flex` and its children had the browser's default `flex-shrink: 1`, squeezing the container to (e.g.) 60% width didn't let `overflow: hidden` cleanly clip stars 4–5 — the flex algorithm instead **shrank all 5 icons proportionally to fit** the narrowed box, which is exactly the "uniform yellowish smear across all 5 stars" from the screenshot. A secondary, smaller issue existed even if `flex-shrink: 0` had been added instead: computing one clip-percentage over the whole 5-star row ignores the 1px inter-star gaps, so the clip boundary wouldn't land exactly on a star edge for fractional averages (imperceptible for whole numbers, but not clean).

**Fix applied — `frontend/src/components/RatingStars.tsx`:** rewritten to render each of the 5 stars as its own independent, fixed-size cell rather than a single shared row. For star index `n` (1–5), `fraction = clamp(average - (n - 1), 0, 1)`: `fraction <= 0` renders the outline `StarIcon` alone, `fraction >= 1` renders `StarFilledIcon` alone, and the at-most-one boundary star with `0 < fraction < 1` renders the outline star as a base plus a `StarFilledIcon` wrapped in an absolutely-positioned span clipped to `{fraction*100}%` width **of that single star's fixed-pixel box** — never a multi-icon row. This eliminates the flex-shrink bug at the root (no multi-star row is ever squeezed) and the gap-skew imprecision (each cell's width is fixed, unaffected by inter-star gaps). The component's public API (`average`, `count`, `size`, `showLabel`, `className`) and the `count === 0` → "Još nema ocjena" branch are unchanged.

**CSS (`frontend/src/index.css`):** removed the dead `.rating-stars-track`/`.rating-stars-empty`/`.rating-stars-filled` rules; added `.rating-stars-row` (the new 5-cell flex row), `.rating-star-cell` (`position: relative`, one star's box), `.rating-star-cell-empty`, `.rating-star-cell-fill` (the per-cell absolute-positioned clipped overlay). No new color tokens — still `--color-star-filled`/`--color-star-empty`.

Since `RatingStars` is the single shared component used everywhere a rating average is shown, this one file fixes all four surfaces (profile, cargo detail, vehicle detail, search cards) at once.

#### Feature: replace the "Ocijeni korisnika" button-gated form with an always-visible, immediately-submitting star input

**Previous UX:** giving a rating required clicking an "Ocijeni korisnika" button to reveal a `RatingPicker` plus a separate "Pošalji ocjenu" submit button — two clicks and a distinct form state before a rating actually landed.

**New UX:** on `CargoDetailPage`/`VehicleDetailPage`'s `#kontakt` card, a logged-in non-owner now sees the interactive picker immediately, no button needed to reveal it — gray/empty by default with the label "Ocijeni korisnika" if they haven't rated this person yet, or filled to their existing score with "Vaša ocjena: N/5" if they have (pre-filled via the existing `ratingsService.getMine()` call, unchanged). **Clicking a star submits immediately** — no separate submit button, no modal, no confirmation step — and clicking a different star afterward updates the same rating the same way (the backend's existing `RatingsService.submitOrUpdate()` already treats a second rating from the same rater as an update, not a duplicate — verified live again this session, not just assumed unchanged).

**Implementation (`CargoDetailPage.tsx` / `VehicleDetailPage.tsx`, both mirrored):**
- Removed: the `showRatingForm` state and its toggle button, the `.rating-submit-panel` block (the "Pošalji ocjenu" button and the `ratingSuccess` state/message), and the `showRatingForm &&` gate.
- `handleSubmitRating` (read `myScore` from state, fired by a button click) was replaced by `handleRate(score)`, called directly from `RatingPicker`'s `onChange`: it optimistically sets `myScore` to the clicked value, submits, refetches the aggregate summary so it updates without a reload, and reverts `myScore` on failure (showing `ratingError`) since there's no longer a separate confirm step to catch a bad submission first.
- `RatingPicker.tsx` itself needed **no changes** — its `onClick={() => onChange(n)}` per star was already "immediate" from the component's own perspective; only the pages' wiring (what `onChange` does) changed.
- The widget is gated on `!isOwner && user` — logged-out viewers see the read-only average only (no non-functional picker with no login-redirect affordance to invent), and the self-rating guard (`isOwner`) is untouched.
- CSS: `.rating-submit-panel` (bordered, padded "revealed panel" look, appropriate for a button-gated form) was replaced with a lighter-weight `.rating-inline-picker` (`display: flex; align-items: center; gap: var(--space-2)`) and `.rating-picker-label` (13px secondary text), appropriate for an always-visible inline row.

**No backend changes** — `RatingsService.submitOrUpdate()`, the unique-pair constraint, and self-rating rejection already supported "submit repeatedly, same row updates" before this session; only the frontend interaction changed.
