# Implemented Features — Session 26

### Session 26 — 2026-08-28

#### Redesign: vehicle & cargo detail pages around a shared component kit

**Previous UX:** `VehicleDetailPage`/`CargoDetailPage` rendered a plain title + `StatusBadge`, then a flat "Podaci o vozilu/teretu" label grid inside generic `.detail-card` blocks, visually disconnected from the redesigned card-based search pages (Session 22's `search-*`/`src-*` CSS system).

**New design**, built from four supplied mockups (desktop/mobile × vehicle/cargo) and a written spec in `CLAUDE.md`: a white header card (3px accent top border) with a mode pill / status pill / cargo-type pill row, a big route headline (origin city — distance + vehicle-type connector — destination city), and 4 fact tiles below a divider; a two-column body below (map + notes on the left, sticky contact + "rate this company" cards on the right on desktop); a horizontal (desktop) / vertical (mobile) dot-and-label cities stepper that collapses to a "+N" expandable node past ~7 cities; a mobile-only sticky bottom action bar.

**Architecture — one shared component set, not copy-pasted per mode:** `frontend/src/components/detail/`:
- `types.ts` — the `DetailData` contract (mirrors the existing `ResultCardData` pattern `ResultCard.tsx` already uses for the list pages: one page-agnostic data object, built by each page from its own `post`, consumed by mode-agnostic presentational components).
- `DetailView.tsx` — composes everything: back link, `DetailHeaderCard`, a `.detail-body` CSS Grid (`grid-template-areas` differs per breakpoint — see below), `MobileActionBar`.
- `DetailHeaderCard.tsx` — pills, route headline + connector, fact tiles, and either `Sačuvaj`/`Podijeli` (real `navigator.share`-or-clipboard-copy behavior; `Sačuvaj` is an honest non-functional button with a tooltip, mirroring the existing `Sačuvaj pretragu` pattern in `SearchPageHeader.tsx` — no saved-listings feature exists anywhere in the app) or, for the listing's own owner, the existing `Uredi` / `Zatvori oglas` / `Obriši` actions in the same slot.
- `RouteMapCard.tsx` — reuses the existing `RouteMap` Leaflet component unchanged, adds a "Otvori cijeli prikaz" link opening a simple centered modal with a larger map, and the cities stepper + mode-specific explainer line.
- `CitiesStepper.tsx` — dot+label stepper, orientation is CSS-only (flex-direction swap at the mobile breakpoint); collapses the middle into an expandable "+N" node past 7 cities.
- `NotesCard.tsx` — returns `null` entirely when the note field is empty (no empty card, no placeholder text).
- `ContactCard.tsx` — optional price block (cargo only), company block, rating stars, masked phone/e-mail that reveal on "Prikaži kontakt" (new `frontend/src/utils/maskContact.ts`; phone/e-mail were already in the payload, no backend change needed), `Pošalji poruku` — all of the contact-action group hidden when the viewer owns the listing.
- `CompanyRatingCard.tsx` — the existing `RatingPicker`, shown only to a logged-in non-owner (unchanged gating from before this session).
- `MobileActionBar.tsx` — sticky bottom bar (route + price/vehicle summary + `Pošalji poruku`), hidden ≥768px and hidden entirely for the listing's own owner.

`VehicleDetailPage.tsx`/`CargoDetailPage.tsx` keep 100% of their existing fetch/edit-form/rating/contact logic (the `isEditing` form is untouched — it wasn't part of the mockups) and just build a `DetailData` object for the non-editing render branch instead of the old flat grid JSX.

**CSS (`frontend/src/index.css`):** a new `.detail-*` section reuses the *same* `--search-accent`/`--search-accent-tint` custom properties the search pages already define, by adding `.detail-page.accent-blue`/`.accent-teal` to the existing selector list that sets those variables — detail and search pages now share one token source rather than redefining the same hex values twice. Layout uses one CSS Grid with `grid-template-areas` that differs by breakpoint rather than reordering/duplicating DOM: desktop (≥1024px) is a 2-column grid with the right-hand column (contact + rating, as two independently-`position: sticky` grid items) sticking as the page scrolls; tablet (768–1023px) collapses to one column with the contact card placed right after the map (non-sticky, no bottom bar); mobile (<768px) moves the contact card directly under the header and adds the sticky bottom bar (with matching `.detail-page` bottom padding so it never covers the last card).

**Backend addition — real route geometry for cargo posts:** the cargo mockup shows the same full "Karta rute" map as the vehicle page, but `CargoPost` had no `routeGeoJson` at all (only `VehiclePost` computed one, via `RouteCityService`). Rather than fake a straight-line "route" or drop the map card for cargo, `CargoPostsService.create()`/`update()` now call the existing `RoutingService`/`OpenRouteService` (the same ORS integration vehicle posts already use) between `loadingCity`/`unloadingCity`, store the result on a new `CargoPost.routeGeoJson` column (migration `1787900000000-AddCargoPostRouteGeoJson`), and regenerate it when either city changes — mirroring `VehiclePostsService`'s existing create/update route-generation pattern exactly, including the same "failure must not block post creation/update" try/catch. The route-coordinate simplification helper (`simplify-route.ts`, using `@turf/simplify`) was extracted out of `RouteCityService` into `backend/src/routing/simplify-route.ts` so both services share it instead of duplicating the tolerance/logic. Cargo posts deliberately do **not** get a cities-on-route table/matching feature — that's vehicle-specific search tooling (`VehiclePostRouteCity` + `RouteCityService.projectCitiesOntoRoute`) that's a much bigger lift to generalize and wasn't asked for; the cargo detail page's stepper instead just shows the two endpoints (loading/unloading) when a route exists.

**Explicitly out of scope, decided with the user before implementation:**
- **Route duration** ("procijenjeno 2 h 20 min" in the mockup) — the ORS integration never captured duration anywhere in the pipeline; adding it would mean a second backend extension beyond the cargo-route one above. Decided to skip it entirely rather than fake a value — the map card subtitle and header connector show only the cached `~ X km` distance (via the existing `useCityDistances`/`POST /cities/distances`, called once per page with a single city pair, same hook the list pages already use).
- **Equipment chips** (mockup shows "Cerada"/"Rampa"/"ADR" as notes-card chips) — there's no backing field for these on either post type (only `cargoType` is a real column), so the vehicle notes card renders no chips at all, and the cargo notes card renders only the real `cargoType` chip. Not faked.

**Bug found and fixed during verification — pre-existing, unrelated to this session's new code:** `.nav-dropdown-panel { position: fixed; left: 16px; right: 16px; }` in the global `@media (max-width: 640px)` block (written for `Navbar`'s user-avatar dropdown) resolves `top: calc(100% + 8px)` — inherited from the base rule — against the *viewport height* once `position` becomes `fixed`, instead of against the trigger. This sent the dropdown panel to the bottom of the screen instead of just below its trigger, on **any** `NavDropdown` usage rendered below 640px width — which already silently affected `SearchPageHeader`'s mobile "more options" menu (Sačuvaj pretraga) on the existing Vehicles/Cargo list pages, and now also affected this session's reuse of the same pattern for the detail pages' mobile Sačuvaj/Podijeli overflow menu. Fixed by keeping the panel `position: absolute` (correctly anchored via `.nav-dropdown { position: relative }`) at that breakpoint and clamping its width with `max-width: calc(100vw - 32px)` instead of switching to `fixed`.
